Update

Updating an Existing ReaClassical Portable Install

Warning

ReaClassical 27 is a new major version. If you are coming from ReaClassical 26 or earlier, do not update in place: run the installer for a fresh copy of ReaClassical 27, which keeps your old install untouched. Updates within the same major version arrive via ReaPack as described below.

Use Extensions > ReaPack > Synchronize packages or press Shift+U (Update ReaClassical). This will sync ReaPack to get the latest ReaClassical functions.

New shortcuts and menu entries need a Factory Reset

ReaPack updates the scripts only. When a release adds new functions to the ReaClassical menu or keymap, they appear in the Action List straight away, but their menu entries and keyboard shortcuts only arrive after a Factory Reset. The release notes say when this is needed.

If a newer major version of ReaClassical is available, Update ReaClassical tells you so and asks you to install the new version fresh instead of updating via ReaPack.

Screen reader users (Clara)

Update ReaClassical works the same way and reports its result through Clara.

Factory Reset

In the ReaClassical top menu, click on ReaClassical Factory Reset (Ctrl+Alt+Shift+F) to return most settings back to those presented at first install. It replaces your keymap, menu, mouse modifiers, render presets, metadata and main REAPER settings (reaper.ini) with the ReaClassical defaults. Existing files are backed up with a .backup extension.

Note

A ReaPack update replaces the ReaClassical scripts but does not touch these REAPER configuration files. If a release changes any of them (for example a new keyboard shortcut, menu entry, toolbar button or render preset), the change will not appear in your install until you run a Factory Reset. A new toolbar button is a good example: its icon arrives with the theme, but the button only shows up once the menu file has been replaced. Check the release notes and run it after updating when a release says so. Any customisations you made to those files are overwritten, so restore them from the .backup files afterwards if needed.

Keeping your customisations through a Factory Reset

If you have customised REAPER yourself (custom actions, control surfaces, your own render presets and so on), plan what to bring back before you run a Factory Reset. Do not copy whole .backup files back over the new ones: that undoes the ReaClassical settings the reset just installed, including any new shortcuts, menu entries or presets from the release. Bring back only your own parts.

Each reset overwrites the previous backup

The .backup files are replaced every time you run a Factory Reset. If you reset twice without restoring anything in between, the second backup holds ReaClassical's defaults and your original settings are gone. Copy the .backup files somewhere safe (or back up the whole resource folder) before resetting if you want to keep them.

To find the files, use Options > Show REAPER resource path in explorer/finder. Close REAPER before editing any of them in a text editor, because REAPER rewrites them on exit.

reaper.ini (main REAPER preferences)

ReaClassical depends on this file: it holds the theme and many of the preferences ReaClassical's workflows need. Don't restore the old file as a whole. Instead, re-enter your own settings in Options > Preferences after the reset. Typical things to check:

  • Control surfaces (for example a Behringer X-Touch) under Preferences > Control/OSC/web
  • External editors under Preferences > External Editors
  • Default paths for recording, rendering and so on
  • Media item display options (item labels, volume knob, lock and FX buttons) under Preferences > Appearance

If you are comfortable editing the file, you can copy individual lines from reaper.ini.backup instead. The control surface lines start with csurf_. Copy csurf_cnt together with the numbered csurf_0, csurf_1 and so on, replacing the csurf_ lines already in the new file rather than adding a second set.

reaper-kb.ini (keymap, custom actions and scripts)

This file holds three kinds of line:

  • KEY lines: keyboard shortcuts
  • ACT lines: custom actions you created
  • SCR lines: scripts you loaded into the Action List

The reset installs ReaClassical's keymap, so your own custom actions and loaded scripts disappear from the Action List. To bring them back without losing ReaClassical's new shortcuts, close REAPER and copy your own ACT and SCR lines from reaper-kb.ini.backup to the end of reaper-kb.ini. Skip any line that refers to a ReaClassical script, because the new file already contains those.

Custom actions and scripts keep their command IDs this way, so anything that triggers actions by command ID (a Stream Deck running Bitfocus Companion, OSC layouts, other scripts) carries on working.

Your own keyboard shortcuts (KEY lines) are better re-assigned by hand in the Action List, because copying them across can clash with ReaClassical's shortcuts. If you skip several releases, check the release notes and the ReaClassical shortcut list for new shortcuts before re-assigning keys of your own.

reaper-render.ini (render presets)

The reset replaces your render presets with the ReaClassical ones. If you saved presets of your own, re-create them after the reset, or (with REAPER closed) copy your own presets from reaper-render.ini.backup into reaper-render.ini. Each preset is a <RENDERPRESET "Name" ... block (ending with a line containing only >) plus a RENDERPRESET_OUTPUT "Name" ... line; copy every line that carries your preset's name, along with the lines inside its block.

Other files

The reset also replaces reaper-menu.ini (menus and toolbars), reaper-mouse.ini (mouse modifiers) and reaper-metadata.ini (metadata presets). If you changed toolbars or mouse modifiers yourself, re-apply those changes through REAPER's toolbar customisation and Options > Preferences > Mouse Modifiers rather than restoring the old files.

Updating REAPER

It is highly advisable to use the version of REAPER that ships with ReaClassical, which is the version ReaClassical has been tested against. Open the Terminal (Ctrl+Enter) and type reaper to install that tested version. reaper=latest installs the newest public release and reaper=752 (for example) installs a specific one. REAPER closes your open projects (it will ask you to save any unsaved work), installs and restarts. Third-party REAPER update utilities are not included in the install package.
